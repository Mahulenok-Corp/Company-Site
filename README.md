# Сайт организации для Google Play Console

Статический сайт-визитка организации: главная страница, политика конфиденциальности, условия использования и страница поддержки. Он нужен, чтобы подтвердить сайт организации в Google Play Console (через Google Search Console), а заодно даёт ссылки, которые Google Play требует в карточках приложений: Privacy Policy, Support, удаление аккаунта.

Без сборщиков и зависимостей: чистый HTML/CSS плюс один скрипт на Node.js, который подставляет ваши данные из `site.config.json` во все страницы.

## Этот репозиторий: Mahulenok-Corp/Company-Site

Сайт настроен на домен **https://mahcorp.xyz**. Публикуется через GitHub Actions на GitHub Pages; до привязки домена он доступен по адресу https://mahulenok-corp.github.io/Company-Site/.

Чтобы домен заработал:

1. Владелец домена добавляет DNS-записи из раздела «Вариант A — GitHub Pages» (четыре A-записи и CNAME для `www`), а также TXT-запись из Search Console.
2. В репозитории: **Settings → Pages → Custom domain** → `mahcorp.xyz` → Save. После успешной проверки DNS включите **Enforce HTTPS**.
3. Проверьте, что https://mahcorp.xyz открывается, затем подтверждайте домен в Search Console (шаг 4) и в Play Console (шаг 5).

## Коротко: что делать

1. Заполнить `site.config.json` (название, домен, email…).
2. Собрать: `node configure.mjs` → готовый сайт в папке `dist/`.
3. Разместить `dist/` на хостинге под своим доменом по HTTPS (ниже — бесплатный вариант через GitHub Pages).
4. Подтвердить домен в Google Search Console (тип «Доменный ресурс», TXT-запись в DNS).
5. В Play Console указать URL сайта и отправить запрос на подтверждение.

Порядок важен: сайт должен открываться по HTTPS **до** шага 4, а домен должен быть подтверждён в Search Console **до** шага 5.

## Что понадобится

- **Собственный домен**, например `mystudio.com`. Регистраторы: Cloudflare Registrar, Namecheap, Porkbun, reg.ru и т. п. Бесплатные поддомены (`*.github.io`, `*.netlify.app`, `*.vercel.app`) Search Console подтвердит, но Google Play может не принять такой сайт как принадлежащий организации — есть риск отказа.
- **Google-аккаунт владельца аккаунта разработчика** Play Console. Если этим же аккаунтом подтвердить домен в Search Console, запрос из Play Console одобрится автоматически.
- **Доступ к DNS-записям домена** (панель регистратора или Cloudflare).
- Node.js 18+ на компьютере (`node -v`).

## Структура проекта

```
site.config.json              все данные организации — единственный файл, который нужно заполнить
configure.mjs                 сборка: src/ + конфиг → dist/
serve.mjs                     локальный предпросмотр dist/ на http://localhost:8080
src/
  index.html                  главная: о компании, приложения, контакты
  privacy.html                политика конфиденциальности
  terms.html                  условия использования
  support.html                поддержка, FAQ, удаление аккаунта и данных (#delete-account)
  404.html
  robots.txt, sitemap.xml
  assets/style.css            стили (акцентный цвет берётся из конфига)
  assets/logo.svg, favicon.svg  логотип-буква (генерируется из названия)
  _partials/                  общие шапка и подвал
.github/workflows/deploy.yml  автодеплой на GitHub Pages
dist/                         результат сборки (в git не хранится)
```

## Шаг 1. Заполнить `site.config.json`

| Поле | Обязательно | Что указать |
|---|---|---|
| `orgName` | да | Название организации — так же, как в Play Console |
| `legalName` | нет | Юридическое название (`… LLC`, `ООО …`). По умолчанию равно `orgName` |
| `domain` | да | Домен без `https://` и без слэшей: `example.com` |
| `siteUrl` | нет | Полный адрес, если сайт живёт на `www`: `https://www.example.com`. По умолчанию `https://<domain>` |
| `email` | да | Основной контактный email |
| `supportEmail` | нет | Email поддержки (по умолчанию равен `email`) |
| `address` | нет | Почтовый адрес организации. Рекомендуется: Google сверяет данные организации |
| `country` | нет | Страна регистрации (используется в разделе «Governing law» условий) |
| `heroLabel` | нет | Короткая подпись над заголовком, например `Independent software studio` |
| `tagline` | нет | Заголовок на главной |
| `description` | нет | Описание в 1–2 предложения (используется и в meta description) |
| `about` | нет | Массив абзацев для раздела About |
| `facts` | нет | Массив `{ "label": "Founded", "value": "2024" }` — карточки фактов |
| `apps` | нет | Массив приложений `{ "name", "description", "status", "url" }`. `url` — ссылка на Google Play, можно оставить пустой. Пустой массив → текст «приложения скоро появятся» |
| `accentColor` | нет | Акцентный цвет в HEX |
| `logoLetter` | нет | Буква на логотипе (по умолчанию первая буква названия) |
| `googleSiteVerification` | нет | Значение атрибута `content` из метатега Search Console. Нужно только для способа «HTML-тег» |
| `lastUpdated` | нет | Дата обновления юридических страниц, `YYYY-MM-DD` |

Тексты страниц лежат в `src/*.html`, их можно править напрямую. Места, которые стоит проверить под свои приложения, помечены комментариями `<!-- EDIT: … -->`. Сайт на английском — это нормально для Google; при желании переведите тексты в `src/`.

## Шаг 2. Собрать и посмотреть

```bash
node configure.mjs
```

```bash
node serve.mjs
```

Откройте http://localhost:8080. Скрипт сборки предупредит, если в конфиге остались значения-заглушки (`example.com`, `Example …`).

## Шаг 3. Разместить сайт

### Вариант A — GitHub Pages (бесплатно, свой домен, HTTPS)

1. Создайте репозиторий на GitHub и запушьте проект в ветку `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. Workflow уже лежит в `.github/workflows/deploy.yml`: при каждом пуше он соберёт сайт и опубликует `dist/`.
3. Там же в поле **Custom domain** введите `example.com` и нажмите Save. Когда DNS проверится (обычно через несколько минут), включите **Enforce HTTPS**.
4. В DNS домена добавьте записи:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | CNAME | `www` | `<ваш-логин>.github.io` |

   Если DNS обслуживает Cloudflare, оставьте прокси выключенным (серое облако), пока GitHub не выдаст сертификат.
5. Через 5–30 минут (в редких случаях до суток) откройте `https://example.com` — сайт должен открываться с замком в адресной строке.

### Вариант B — Netlify, Cloudflare Pages, Vercel

Подключите репозиторий и укажите **Build command** `node configure.mjs`, **Publish directory** `dist`. Домен подключается в настройках проекта — сервис сам покажет нужные DNS-записи и выдаст HTTPS.

### Вариант C — любой обычный хостинг

Загрузите **содержимое** папки `dist/` в корень сайта (`public_html`, `www` и т. п.) и убедитесь, что включён HTTPS.

## Шаг 4. Подтвердить домен в Google Search Console

Войдите в Search Console **тем же Google-аккаунтом, что и в Play Console** (владельцем аккаунта разработчика).

1. Откройте https://search.google.com/search-console и нажмите «Добавить ресурс».
2. Выберите **«Доменный ресурс»** (левый вариант) и введите домен: `example.com` — без `https://`.
3. Search Console покажет TXT-запись вида `google-site-verification=XXXXXXXX`. Добавьте её в DNS домена:

   | Тип | Имя | Значение |
   |---|---|---|
   | TXT | `@` | `google-site-verification=XXXXXXXX` |

4. Нажмите «Подтвердить». Если ошибка — DNS ещё не обновился: подождите 10–60 минут и нажмите снова. Проверить, что запись уже видна, можно командой:

```bash
dig TXT example.com +short
```

Почему именно «Доменный ресурс»: он покрывает `http` и `https`, `www` и без `www`, все поддомены — поэтому URL, введённый в Play Console, гарантированно совпадёт с ресурсом. Ресурс «с префиксом URL» должен совпадать с адресом в Play Console символ в символ, и это самая частая причина ошибки «не удалось подтвердить».

Если доступа к DNS нет, создайте ресурс **«С префиксом URL»** (`https://example.com/`) и используйте один из способов:

- **HTML-тег**: скопируйте значение `content="…"` из предложенного метатега в поле `googleSiteVerification` в `site.config.json`, пересоберите и задеплойте сайт.
- **HTML-файл**: положите скачанный файл `google….html` в папку `src/` — сборка скопирует его в корень сайта как есть.

## Шаг 5. Подтвердить сайт в Play Console

1. Play Console → **Настройки → Аккаунт разработчика → Сведения об аккаунте**.
2. В разделе с данными организации найдите поле **«Сайт организации»**, укажите `https://example.com` и сохраните.
3. Рядом с полем нажмите **«Подтвердить»** (отправить запрос на подтверждение).
4. Что происходит дальше:
   - домен в Search Console подтверждён **тем же аккаунтом** — запрос одобряется автоматически, статус «Подтверждено» появляется сразу или в течение нескольких минут;
   - домен подтверждён **другим аккаунтом** — его владелец получит письмо и уведомление. Одобрить нужно в Search Console: **Настройки → Ассоциации → Ожидающие запросы → Одобрить**. Это может сделать только пользователь с ролью «Владелец» ресурса.
5. После одобрения придёт письмо и сообщение во «Входящих» Play Console о том, что связь между сайтом и аккаунтом разработчика создана.

## Типичные проблемы

| Симптом | Причина и решение |
|---|---|
| Play Console: «не удалось подтвердить сайт» | URL не совпадает с ресурсом Search Console (`www`/без, `http`/`https`, слэш в конце). Создайте доменный ресурс или введите URL точно как в Search Console. |
| Запрос отправлен, ничего не происходит | Домен подтверждён другим Google-аккаунтом. Зайдите в Search Console этим аккаунтом → Настройки → Ассоциации → Одобрить. |
| В Search Console нет кнопки «Одобрить» | Нужна роль «Владелец» (подтверждённый). Пользователь с «Полным доступом» одобрять не может. |
| Search Console не видит TXT-запись | DNS ещё не обновился, либо запись добавлена на поддомен. Имя записи должно быть `@` (корень домена). |
| Google Play отклоняет сайт | Сайт на бесплатном поддомене хостинга, либо название организации на сайте не совпадает с юрлицом в аккаунте. Используйте свой домен и заполните `legalName`. |
| Сайт открывается по `http`, но не по `https` | На GitHub Pages сертификат выдаётся после проверки DNS — подождите и включите Enforce HTTPS. На Cloudflare выключите прокси до выдачи сертификата. |

## Что ещё пригодится при публикации приложений

Не нужно для подтверждения организации, но Google Play спросит это при публикации:

- **Политика конфиденциальности** для каждого приложения: `https://example.com/privacy.html`. Отредактируйте список SDK в разделе 3 файла `src/privacy.html` под реальные практики.
- **Удаление аккаунта и данных** (раздел Data safety, если в приложении есть аккаунты): `https://example.com/support.html#delete-account`.
- **Email поддержки** в карточке приложения — `supportEmail`.
- **App Links / Digital Asset Links**, если понадобятся: положите файл `src/.well-known/assetlinks.json` — сборка скопирует его в `dist/.well-known/`.

## О юридических текстах

Privacy Policy и Terms of Use — типовые англоязычные шаблоны для сайта и мобильных приложений. Они покрывают стандартные случаи (аналитика, крэш-репорты, реклама, покупки через Google Play), но не заменяют консультацию юриста. Перед публикацией проверьте:

- какие SDK реально используются (раздел 3 Privacy Policy);
- адресованы ли приложения детям (раздел 7 Privacy Policy);
- применимое право в Terms (раздел 11, подставляется `country`).
